# Documentation Standards

## Principles

- Concise, high-signal; prefer examples and short lists over long paragraphs
- Write for the reader's skill level
- Consistent terminology
- Keep docs up-to-date as code changes

## Structure

- README: overview, quick start, usage
- Technical docs: architecture, configuration, troubleshooting
- Project docs go in the project root's `docs/` folder (not the root)

## Rules

- Test all code examples
- Maintain consistency with naming conventions and architecture decisions
- DO NOT create documentation files proactively - only when asked
